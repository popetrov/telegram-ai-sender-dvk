# Согласованные требования и критерии готовности

## Главный принцип: универсальное ядро и подключаемый бизнес

Техническое ядро общее для всех компаний и продуктов. Подключение нового
бизнеса, использующего поддерживаемые возможности, не требует изменений ядра
или создания отдельной ветки. Не привязывать механизмы доступа, очередей,
хранения, отправки, обновления и синхронизации к названиям компаний/продуктов.

Бизнес подключается конфигурацией компании и продуктовыми пакетами:
идентификатор продукта, алиасы из Excel, схема входных данных, промпт,
настройки необходимых источников/инструментов и проверки результата.
Текущий пользовательский сценарий сохраняется: продукт задаётся в Excel,
программа выбирает соответствующий сценарий и промпт.

Новые внешние интеграции могут требовать разработки отдельного адаптера через
общий интерфейс. Не обещать поддержку неизвестного API одним промптом.
Логику конкретного бизнеса держать в продуктовом пакете/адаптере. Общие
интерфейсы расширять совместимо. Пакеты версионировать и проверять при загрузке.

Критерий: два независимых бизнеса работают на одном ядре; новый продукт на
поддерживаемых инструментах подключается конфигурацией без правки ядра.
Судебные источники текущих продуктов — пример существующей связности для
выноса в адаптер, а не универсальный обязательный шаг любого бизнеса.

## Общая платформа Windows/macOS и стабильность

- Одно техническое ядро и общий цикл версий; отдельные установщики/запуск для ОС.
- По сообщению владельца 15 действующих менеджеров используют 2.0.19 и start.bat;
  их фактические версии ещё нужно подтвердить при пилоте.
- Рабочая установка владельца проверена отдельно: Windows, 2.0.9,
  feature/auto-updates, HEAD 1b4e2fc, запуск python main.py. Локальные продукты
  и промпты сохранить. Владелец сохраняет прямой запуск и обновляется вручную
  проверенными версиями. Химикаты для растений — приостановленный черновик.
- Отдельную macos-support-2.0.19 объединять с общей платформой с сохранением
  поддерживаемых сценариев; не считать нынешнюю замороженную сборку обновляемой.
- Простое подключение с диагностикой зависимостей, настроек и авторизации.
- Отказы сети и перезапуск не теряют подготовленные данные, очередь и исходы.
- Не повторять отправку с неопределённым исходом автоматически.
- Понятные пользователю ошибки и диагностические журналы без секретов.

## Обновления — обязательное условие выпуска

- Проверить переход с реально установленной 2.0.19, а не только чистую установку.
- Сохранять .env, Telegram-сессии, локальную SQLite и настройки пользователей.
- Доставлять новые модули и зависимости совместимым способом.
- Проверять целостность пакета, совместимость и миграции до активации.
- Подтверждать успешный запуск и восстановление прежнего состояния при сбое.
- Не прерывать активную отправку ради обновления.
- Проверять оба установщика и обновления на Windows/macOS до общего выпуска.
- Текущий фиксированный allowlist обновлятора 2.0.19 требует отдельного плана
  совместимого перехода; новые файлы нельзя просто добавить в старый архив.

## Центр, компании и доступ

Центр работает на компьютере владельца, отдельный административный Telegram-бот
@asdvk2026_bot служит интерфейсом. Токен хранится только у владельца.
@baza_dvk_bot — рабочий бот рассылки, не менять его назначение.

- ДВК Финанс, ДВК Право, ДВК Закупки считаются одной компанией ДВК с бесплатным
  бессрочным доступом. Можно отозвать доступ отдельного менеджера.
- Остальные компании оплачивают компанию независимо от числа менеджеров;
  стоимость владелец определяет вручную.
- Период: календарный месяц + 2 дня. При отсутствии соответствующего числа
  использовать последний день целевого месяца, затем добавить 2 дня.
- Согласованное правило продления: от текущего окончания действующей подписки,
  от момента продления — для уже истёкшей. Часовой пояс расчёта и отображение
  даты должны быть явными до внедрения.
- Возможны отзыв компании целиком и отзыв отдельного менеджера.
- Проверка разрешения каждые 5 минут через Telegram; учитывать задержку сети.
- Автономное разрешение максимум 24 часа с последней успешной проверки.
- Срок разрешения ограничен окончанием подписки; офлайн-режим его не продлевает.
- Перезапуск не продлевает срок. Отзыв сохраняется между перезапусками.
- При отзыве/истечении остановка до следующей отправки и новой подготовки;
  уже начатый внешний запрос невозможно отозвать задним числом.
- Данные сохраняются. После восстановления доступа продолжение с явным
  подтверждением, без повторной отправки уже обработанных сообщений.

## Синхронизация исключительно владельцу

Собирать данные ВСЕХ пользователей, включая внешних покупателей:
клиентские записи, выбранный продукт, анализы ИИ, подготовленные сообщения,
статусы/время/ошибки отправок и идентификаторы отправленных сообщений.

- Ответы клиентов и дальнейшую переписку в этой итерации не собирать.
- Другим менеджерам центральные данные не выдавать. Общую межменеджерскую
  проверку дублей в эту итерацию не добавлять.
- Сначала надёжная локальная запись, затем передача в центр; при недоступности
  центра накапливать изменения и возобновлять передачу после восстановления.
- Устойчивые ID компании, установки и записи; идемпотентная доставка,
  подтверждения получения, повторные попытки и правила обновления записей.
- Сохранить принадлежность данных компании/менеджеру; не смешивать клиентов
  разных компаний из-за совпадения локальных числовых ID.
- Telegram-сессии, пароли, токены и API-ключи в центральную базу не собирать.
- Для внешних покупателей сбор данных явно отражается в условиях подключения.

## Проверки перед выпуском

Чистая установка и обновление 2.0.19 на обеих ОС; сохранность пользовательских
файлов; повреждённый/недоступный пакет; откат и миграции базы; два разных
бизнес-пакета на одном ядре; одобрение, отзыв менеджера и компании; продление,
истечение подписки и календарные границы; отключение центра, истечение 24 часов,
перезапуск; очередь без повторных отправок; накопление и повторная доставка
синхронизации без дублей; отсутствие раздачи данных другим менеджерам.

## Фактическое состояние

В локальной feature/central-access-leases есть черновик подписанных автономных
разрешений, отдельного центра и проверок в подготовке/отправке. 56 тестов прошли
в Linux без реальных отправок. Это не подтверждает работоспособность настоящего
Telegram-центра, обновления с 2.0.19, Windows или macOS.

Выделен первый продуктовый слой: реестр пакетов, настраиваемые поля Excel,
модель/инструменты ИИ и явные адаптеры источников; существующие продукты ДВК
подключены через тот же механизм. Пример независимого бизнеса — examples/service_business.
См. BUSINESS_PACKAGES.md для границ этого этапа.

Добавлены общий start.py и оболочки Windows/macOS, а также manual_update.py для
подготовки отдельной копии с сохранением локальных данных/промптов. Репетиция на
реальном базовом коммите 1b4e2fc и имитации локальных правок прошла. Настоящие
пользовательские файлы и рабочая установка владельца в облако не передавались.
См. MANUAL_UPDATES.md: подготовка не активирует копию и не доказывает её готовность.

Подписки компаний, синхронизация, живые проверки обеих ОС и совместимый
автоматический выпуск ещё не реализованы/не проверены. Релиз не опубликован,
действующие установки менеджеров не изменены.

Рабочая последовательность: определить границы общего ядра и интерфейсы
бизнес-пакетов; подготовить общую базу Windows/macOS и безопасный путь обновления;
интегрировать компании/подписки и сбор данных; провести сквозные проверки и пилот;
только затем выпуск для действующих менеджеров.
