# Внутренняя таблица менеджеров

ФИО, номер, направление и название компании задаёт только владелец в личном чате
админ-бота. Менеджер не получает этих полей: они не включаются в разрешение доступа,
ответы технического бота или менеджерский пакет. Обычные права доступа сохраняются.
Таблица и её существующие права общего доступа автоматически не меняются.

После /approve ID КОМПАНИЯ доступ выдаётся как раньше. Для нового менеджера
админ-бот дополнительно спрашивает четыре поля по одному. Для уже существующего
профиля повторное /approve не создаёт новую карточку. Изменение карточки: /profile ID.
Отмена ввода: /cancel (не отзывает доступ). Прерванное заполнение сохраняется в базе
центра и продолжается после перезапуска. Номер уникален; нули в 001 сохраняются.

Сначала карточка надёжно сохраняется в SQLite центра, затем отдельный процесс
передаёт её Google. Недоступность Google не блокирует разрешения, рассылку и сбор
данных. Подтверждение подписано и связано с ID запроса, Telegram ID и ревизией.
Без корректного подтверждения карточка остаётся в очереди. Новая правка во время
отправки не считается доставленной по старому подтверждению.

## Однократное подключение (пока не выполнено автоматически)

Подключение Google Drive в Codex позволяет редактировать файл из чата, но не выдаёт
локальному центру самостоятельные полномочия Google. Для работы без открытого Codex
используется небольшой Google Apps Script, выполняемый от имени владельца таблицы.
Новых Python-зависимостей и Google Cloud service account не требуется.

1. В нужной таблице откройте Расширения → Apps Script. Добавьте новый файл
   DVK_Roster и вставьте содержимое google_roster_bridge.gs. Если в проекте уже
   есть doPost, существующий обработчик не заменять — нужна проверка конфликта.
2. Сохраните. Запустите setupDvkSync и разрешите доступ к своей таблице.
   Окно в таблице покажет секрет. Не присылайте его в чат.
3. Развернуть → Новое развертывание → Веб-приложение. Выполнение — от своего
   имени; доступ к самому endpoint — «Все». Таблицу при этом публичной не делать.
   Запись разрешена только запросам с правильной подписью и действующим временем.
4. Скопируйте адрес вида https://script.google.com/macros/s/.../exec.
5. Остановите центр. В папке центра выполните center.bat sheets-config. Укажите
   адрес и секрет (секрет вводится скрыто). Запустите центр обычным способом.
6. Проверка на действующем аккаунте владельца: /profile 925600480. Введите
   соответствующие реальные поля и существующий номер. Проверьте строку в таблице.
   Код без этой живой проверки не объявляется полностью подключённым.

## Поведение таблицы

Скрипт жёстко ограничен указанной владельцем таблицей «Менеджеры бота», лист «Лист1».
Видимые A:D: ФИО, Номер, организация, Компания. Служебные E:F: Telegram ID и ревизия;
эти два столбца скрываются. При посторонних данных в E:F автоматическая запись
останавливается, чтобы не перезаписать их. Скрытие столбца — оформление, не механизм
секретности; права доступа к таблице остаются под управлением владельца.

Дубли исключаются по Telegram ID, а не по имени. Для старой строки без ID связь
добавляется только при совпадении номера и точного ФИО, введённых владельцем.
Занятый другим менеджером номер и неоднозначные совпадения не перезаписываются.
Старый HTTP-запрос не заменит более новую ревизию карточки.
Пользовательский текст записывается как literal rich text, никогда как формула.

Компания указывается в строке её менеджера/представителя. Отдельные строки без
менеджера в этот реестр не добавляются: текущие четыре столбца описывают людей.
Создание или включение компании без менеджера само по себе не создаёт фиктивного ФИО.

Секрет хранится в Script Properties Google и data/access_authority/sheets.json центра;
его нет в репозитории, логах, ссылках или пакетах менеджеров. После изменения скрипта
нужно выпустить новую версию развертывания Google. При изменении секрета повторно
настройте центр. Сохранять секрет и конфигурацию нужно отдельно от публичного кода.
