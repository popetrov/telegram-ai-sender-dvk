# Однократное обновление отдельной Mac-сборки 2.0.19

В ветке `macos-support-2.0.19` проверка GitHub намеренно отключена. Опубликованный релиз сам не может изменить уже установленный клиент.

Дополнительный архив `dvk-macos-update-2.0.20.zip` содержит один исполняемый файл `Обновить ДВК.command` и инструкцию. В файл встроен официальный опубликованный переходный архив 2.0.20 с закреплённой контрольной суммой. Настройки и секреты пользователя в пакет не входят.

1. Закрыть работающую программу рассылки и её окно Terminal.
2. Распаковать архив и перенести `Обновить ДВК.command` в существующую папку программы рядом со `start_mac.sh`.
3. Открыть файл обновления и дождаться установки. Нужны интернет и Python 3.11+.
4. Владелец центра выдаёт доступ этому аккаунту в нужной компании и устанавливает оплаченный срок. Подключение не назначает компанию автоматически.

Файл проверяет исходный код именно замороженной Mac-сборки. При неизвестных изменениях он прекращает переход. Старый обновлятор создаёт резервную копию, новый установщик готовит отдельную рабочую папку, проверяет зависимости и локальную базу и сохраняет указатель активной версии. Старые настройки, сессия, MANAGER_ID, продукты и данные переносятся обычным переходным установщиком.

Существующий `start_mac.sh` сохраняется и через новый launcher запускает активную версию. После первого перехода он также проверяет новые стабильные релизы. Сохранённая очередь автоматически не запускается.

Для автоматической проверки на macOS используется тот же сгенерированный `.command`, реальный исходный код замороженной ветки и искусственные настройки/база. Флаг `--check-only` выполняет установку и локальную проверку без подключения Telegram или отправки клиентам. Проверка живой установки клиента выполняется отдельно.

Сборка и публикация дополнительного архива выполняются workflow `macos-frozen-update.yml` по тегу `mac-activation-2.0.20`, после успешной проверки на macOS. Он добавляет два файла к существующему v2.0.20 без замены основных архивов или изменения latest.
