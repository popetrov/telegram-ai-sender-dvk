# СОЗДАНИЕ PROMPT ДЛЯ НОВОГО ПРОДУКТА

## Главное правило

Для добавления нового продукта **код программы менять не нужно**.

Вся логика конкретного продукта должна находиться только в его prompt-файле.

Механика бота является универсальной и не должна зависеть от того, какой именно продукт обрабатывается.

Например:

```text
prompts/bg.md
prompts/credit.md
prompts/factoring.md
prompts/leasing.md
```

Если появляется новый продукт, менеджер создаёт новый `.md` файл в папке `prompts`.

После этого бот автоматически использует соответствующий prompt в зависимости от значения в колонке `Продукт` в Excel.

# ЧТО ТАКОЕ PRODUCT PROMPT

Product prompt — это инструкция для ИИ, которая полностью описывает:

* что представляет собой продукт;
* кому он подходит;
* какие проблемы решает;
* в каких бизнес-ситуациях возникает потребность;
* какие признаки потребности искать у компании;
* что исследовать через Web Search;
* какие бизнес-крючки использовать;
* как связывать найденную информацию с продуктом;
* какую ценность работы с нами показывать;
* какие реальные кейсы использовать;
* какие утверждения запрещены;
* какие формулировки запрещены;
* каким должен быть стиль сообщения;
* какую цель должен выполнять первый контакт;
* каким должен быть финальный результат исследования и сообщения.

Prompt должен быть написан так, чтобы другой менеджер, который не знает внутреннее устройство программы, мог взять только этот файл и понять, **как ИИ должен работать с данным продуктом**.

# КРИТИЧЕСКОЕ ПРАВИЛО: НЕ СМЕШИВАТЬ ПРОДУКТ И МЕХАНИКУ

В prompt описывается только **логика продукта и логика работы ИИ с клиентом**.

В prompt НЕ нужно описывать:

* Python;
* Excel-загрузку;
* Telegram API;
* SQLite;
* PostgreSQL;
* структуру базы данных;
* названия Python-файлов;
* функции программы;
* обработку Telegram-папок;
* поиск дублей в Telegram;
* сохранение результатов в БД;
* отправку сообщения через Telethon;
* техническую обработку ошибок;
* работу программы с файлами.

Это уже реализовано в механике бота.

Prompt должен быть независимым от программной реализации.

# КАК СОЗДАТЬ PROMPT

Перед созданием prompt собери всю подтверждённую информацию о продукте.

Не нужно писать prompt на основе общих представлений о продукте.

Сначала собери:

1. Что представляет собой продукт.
2. Какую задачу клиента он решает.
3. Для каких компаний он предназначен.
4. В каких ситуациях возникает потребность.
5. Какие признаки этой ситуации можно обнаружить в открытых источниках.
6. Какие виды бизнеса особенно релевантны.
7. Какие бизнес-события могут быть поводом для обращения.
8. Какие реальные кейсы есть у компании.
9. Какую подтверждённую ценность можно показать клиенту.
10. Какие условия действительно существуют.
11. Какие утверждения запрещено делать.
12. Какие формулировки не используются в продажах.

После этого информация переносится в prompt.

# PROMPT ДОЛЖЕН ОПИСЫВАТЬ НЕ ТОЛЬКО ПРОДУКТ, НО И ЛОГИКУ ИССЛЕДОВАНИЯ

ИИ получает данные компании и должен самостоятельно провести исследование через Web Search.

Поэтому в prompt нужно объяснить:

**что именно искать;**

**зачем это искать;**

**какие найденные факты считать релевантными;**

**как отличать факт от предположения;**

**как найденный бизнес-контекст связывать с продуктом.**

Не достаточно написать:

> Ищи информацию о компании и подумай, нужен ли ей продукт.
