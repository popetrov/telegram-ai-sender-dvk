# Переход с 2.0.19 в новую папку

Это отдельный переходный комплект. Он не используется старым автообновлятором
и не заменяет рабочую установку автоматически. Реальный Mac проверяется отдельно
26 октября 2026; до этого общий выпуск всем менеджерам не разрешён.

Что нужно: Python 3.11+, интернет для зависимостей, свободное место для копии базы,
настроенный центр владельца. Токены и Telegram-сессии не присылайте в чат.
Файл center-public.json содержит только имя технического бота и публичные ключи.

1. Скачайте весь переходный ZIP и его .sha256. Сравните контрольную сумму:

```cmd
certutil -hashfile dvk-transition-pilot.zip SHA256
```

2. Распакуйте комплект в отдельную папку. Остановите старую программу и её окно
   запуска. Для старой версии 2.0.19 установщик не может автоматически доказать
   остановку, поэтому требуется ваше подтверждение. Не запускайте обе копии вместе.
3. Откройте CMD в папке комплекта и выполните:

```cmd
transition.bat
```

Укажите полный путь к старой папке. После остановки введите STOPPED.
Рядом будет создана папка с суффиксом _new. Она должна отсутствовать до перехода.

Установщик проверит комплект и старый код, перенесёт данные и локальные продукты,
создаст отдельное окружение, установит зависимости, настроит публичные ключи
центра и проверит локальную базу и каталог. MANAGER_ID, личные ключи и сессия
сохраняются. Другой существующий ключ центра молча не заменяется.

Поддерживаемые исходные варианты: Windows 2.0.19, отдельная macOS 2.0.19 и
рабочая ветка владельца 2.0.9 на 1b4e2fc. Изменённые файлы технического ядра
требуют отдельной проверки; продукты и промпты сохраняются с отчётом о конфликтах.
Повторный запуск поверх уже созданной новой папки запрещён.

Проверка переноса без установки зависимостей и запуска:

```cmd
transition.bat --source "C:\путь\старая_папка" --destination "C:\путь\новая_папка" --sender-stopped --prepare-only
```

4. Проверьте update_report.json и transition-report.json в новой папке.
   Если есть конфликты или ошибка, новая установка не объявляется готовой.
   Исходная папка остаётся доступной для возврата.
5. Только после успешных локальных проверок запустите start.bat из новой папки.
   Новый менеджер должен получить одобрение /approve ID КОМПАНИЯ в центре.
   Проверка /access и первая контролируемая отправка выполняются отдельно:
   установщик сам не отправляет сообщения и не подтверждает сетевой запуск.

При ошибке остановите новую программу и запустите старую из сохранённой папки.
Если из новой копии уже отправлялись сообщения, нельзя слепо повторять их из
старой базы: сначала сверяйте результаты и чаты. Автоматического объединения
двух разошедшихся баз нет. Этот способ возврата рассчитан прежде всего на сбои
до начала новых отправок; автоматическое обновление с откатом остаётся отдельной задачей.

macOS: оболочка `bash transition_mac.sh` использует тот же установщик. После
перехода запуск — `bash start_mac.sh`. Автопроверки на macOS не заменяют
согласованный живой запуск 26 октября.
